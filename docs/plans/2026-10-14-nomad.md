# Project NOMAD support

Goal, in a NOMAD owner's words: "I pointed Zimi at my NOMAD box and everything was just there, and anything I download in either shows up in both."

## What NOMAD is (read from its repo, `Crosstalk-Solutions/project-nomad`, main at 54ee30a, 2026-10-05)

- Installs on Debian-based hosts (Ubuntu 26.04 LTS recommended, 24.04 and Debian 12 supported) by a terminal script, `install/install_nomad.sh`, or by hand from `install/management_compose.yaml`. Windows is community-supported through WSL2. Minimum 2 GHz dual core, 4 GB RAM, 5 GB disk; the AI assistant is what needs a GPU and 25 GB or more. (README, "Installation & Quickstart", "Device Requirements".)
- It is a management UI ("Command Center", port 8080, no authentication) that starts other containers through the Docker socket. Compose runs `nomad_admin`, MySQL, Redis, Dozzle, an updater sidecar and a disk collector.
- Storage: the admin container mounts a host folder at `/app/storage`, default `/opt/project-nomad/storage` (`management_compose.yaml`, `install_nomad.sh` `NOMAD_DIR`). Every child app is pointed at the same host folder. The compose comments say to move storage by moving the data and changing the left side of the mount, keeping subfolders (`zim`, `models`) intact.
- ZIMs: `<storage>/zim`, flat. `admin/app/utils/fs.ts` has `ZIM_STORAGE_PATH = '/storage/zim'` and `KIWIX_LIBRARY_XML_PATH = '/storage/zim/kiwix-library.xml'`. Kiwix is `ghcr.io/kiwix/kiwix-serve` started with `--library /data/kiwix-library.xml --monitorLibrary` (`admin/constants/kiwix.ts`), so it serves whatever the XML lists.
- Downloads are staged as `<name>.zim.tmp` and renamed when complete (`admin/app/utils/downloads.ts`), so a `.zim` in that folder is a whole file.
- What is installed is recorded in NOMAD's MySQL, not in a file: `installed_resources` (resource_id, type `zim` or `map`, version, url, file_path, size) and `zim_file_metadata` (migrations under `admin/database/migrations`). There is no manifest Zimi could read, and none is needed: the folder is the truth Kiwix serves.
- Updates: releases 1.33 and later add opt-in automatic updates of installed ZIMs and PMTiles maps, which replace the file (`collection_update_service.ts`, `run_download_job.ts` deletes only the replaced resource's own previous file). A "Rescan Library" button rebuilds `kiwix-library.xml` for files sideloaded into the folder. (Release notes v1.33.0 and v1.35.0.)
- Maps: ProtoMaps PMTiles, `<storage>/maps/pmtiles`. Kolibri (Khan Academy) keeps its own folder, `<storage>/kolibri-gen2`. AI: Ollama (default port 11434; a remote Ollama or any OpenAI-compatible server can be set in the assistant's settings) plus Qdrant for RAG; NOMAD can embed ZIM content into that knowledge base (issue #1119 asks for an opt-out). Other apps arrive through its Supply Depot catalog.

## Design (jony-ive-review applied to the plan)

**The one job:** my NOMAD library is in Zimi, and stays in step, without my doing anything again.

Already right in the shape: Zimi already scans one folder and one level of subfolders with a collision rule, and already splices single files in and out of the live library (`register_zim_file`, `unregister_zim_file`). The new thing is only a lower tier in that rule, so the model stays "one library".

Findings and what was done:

- Hierarchy: the Storage card now has a fourth field. It sits under the two folders and stays quiet: an empty list shows only the add field and one sentence. The NOMAD offer is the only loud thing and shows only when NOMAD is found and not yet answered. Done.
- Inevitability: the half-way house ("copy NOMAD's files in") was rejected. A copy is 100 GB more disk and drifts the moment NOMAD updates. Reading in place is the only shape where "anything I download in either shows up in both" is true without a sync script. Eight folders at most, a number chosen so a list cannot grow unbounded, not a product claim.
- Order: one rule everywhere, ownership. A folder is Zimi's (library root and its subfolders) or someone else's (extra folders). Someone else's is never deleted from, renamed in or updated, and loses name collisions. Delete, Update and update checks all ask the same function (`libfolders.owner`). Nothing else needed a rule.
- Care in the unseen: a drive that is unplugged keeps its row, says "Not reachable right now" and comes back; a file still being copied is not opened until its size holds for a tick; an update that replaces a file leaves one entry; a failed add says why in the card's own words (ten languages); a non-primary admin cannot name a server path (the same rule as Create's Folder and Import).
- Honesty: Delete is not greyed out, it is replaced by whose the ZIM is. The "Installed" badge is dropped on those rows, because it said nothing the label does not.
- Cut: a "sync to NOMAD" feature (writing Zimi's downloads into NOMAD's folder and its Kiwix XML). NOMAD owns that XML and its database, and writing beside them breaks its record of what it installed. The guide offers the one safe way to share one folder (mount it as Zimi's library) with its costs said plainly.

Nothing is added to a primary path. The scan gains one extra directory listing per extra folder at boot and on reload. The watcher is one directory listing per folder every 30 seconds in a background thread. The card asks the disk when Settings opens.

## Built

- `zimi/libfolders.py`: the folder list (`ZIMI_EXTRA_ZIM_DIRS`, config key `extra_zim_dirs`, and `library_folders.json` in the data folder), `owner`, `add`, `remove`, `dismiss`, `suggestions` (the NOMAD offer at `/opt/project-nomad/storage/zim` and `/nomad`), the watcher.
- Scan tier 2 and the same tier in `register_zim_file`'s collision test.
- `GET/POST /manage/library-folders`, `external` on `/list` entries, Delete refused with 403 for those ZIMs, update checks skip them, the catalog counts them as installed.
- Storage card, the label where Delete was, ten locales.
- `docs/integrations/project-nomad.md`, linked from the README.

## Parked, with the place to pick it up

- **Zimi's AI setting and NOMAD's Ollama.** When the Studio ships an AI setting, a NOMAD box is the likeliest home for the model: Ollama on `http://<nomad-host>:11434` (NOMAD documents `OLLAMA_HOST=0.0.0.0` for a remote one) or any OpenAI-compatible URL. The setting should accept a base URL and a model name, not assume NOMAD. Nothing is built here.
- **NOMAD's maps.** PMTiles are a single-file format Zimi's MapLibre pages could read with the `pmtiles` JS library; Zimi's Maps app today reads StreetZim ZIMs. Worth doing if NOMAD users ask; it is a new reader, not part of this change.
- **Detecting NOMAD through Docker** (the admin container's mount) so a Dockerised Zimi on the same host finds it without a path. It needs the Docker socket, which Zimi should not ask for. The documented mount is one line.
- **Subfolders of an extra folder.** NOMAD and Kiwix are flat. Add if someone's layout needs it.
- **A scheduled re-listing for slow network mounts** is not needed: the watcher already costs one listing.

## Later: moving a NOMAD ZIM into Zimi (1.15.x, not built)

Asked for: some way to bring a ZIM into Zimi's own folder, and with it Zimi's management (delete, update, categories). Options and what each costs:

- **Move.** Zimi's folder gets the file, NOMAD's folder loses it. NOMAD's database (`installed_resources`) still lists it, its Kiwix XML points at a missing file, and its auto-update may fetch it again. It breaks the other program, which is the thing this release promised not to do.
- **Copy.** Safe for NOMAD and simple, but a Wikipedia is tens of gigabytes: double the disk, a long copy on a small box, and the two drift apart the moment NOMAD updates its own.
- **Let Zimi manage updates inside NOMAD's folder.** Mount the folder read-write as Zimi's library (already documented). Zimi's updates then replace files NOMAD's database believes it owns, and NOMAD's records go stale unless NOMAD is told (its Rescan Library button rebuilds the XML but not its install records). Not something Zimi can do quietly.
- **Adopt by hardlink, copy when it cannot link** (recommended). A hardlink gives Zimi its own name for the same bytes: no extra disk, no change to NOMAD's file or records, instant. If NOMAD later updates, it writes the new edition and deletes the old name, and Zimi's link keeps the old edition intact until Zimi updates or deletes it; from then on the ZIM is Zimi's (Delete, Update, categories, seeding all work). It needs the two folders on one filesystem and writable, so a `:ro` mount cannot do it; then the flow offers a real copy with the size and free space stated first. Per ZIM, one tap ("Make Zimi's own copy"), never automatic, with the disk cost said before it happens. Mark for 1.15.x.
